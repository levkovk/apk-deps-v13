# Граф зависимостей Alpine apk

Вариант 13. Программа показывает зависимости пакетов Alpine Linux
(формат apk). Список зависимостей она читает сама из индекса
репозитория. Команду `apk` и чужие библиотеки для этого не вызывает.

Язык программы — Python 3. Ставить дополнительные пакеты не нужно.
Нужна только стандартная библиотека.

## Этап 1. Параметры

Программа читает настройки из командной строки и печатает их
парами `ключ=значение`.

Параметры:

- `--package` — имя пакета. Для Alpine это строчные буквы, цифры,
  точка, плюс, подчеркивание и дефис. Пример: `musl`.
- `--repo` — адрес репозитория (`http://` или `https://`) либо,
  в тестовом режиме, путь к файлу.
- `--test` — включить тестовый режим. Тогда `--repo` — это путь
  к файлу, а не адрес в сети.
- `--version` — версия пакета, как в индексе Alpine.
  Пример: `1.2.5-r12`. В тестовом режиме версию можно не писать.
- `--filter` — подстрока. Пакеты, в имени которых она есть,
  дальше не разбираются. Пустое значение значит, что фильтр
  выключен.

Если параметр пустой или записан неверно, программа пишет
`ошибка: ...` в stderr и завершается с кодом 1.

## Этап 2. Прямые зависимости

Программа скачивает из репозитория файл `APKINDEX.tar.gz`.
Внутри архива лежит текст `APKINDEX`. Один пакет — один блок.
Блоки разделены пустой строкой.

Из блока берутся три поля:

- `P` — имя пакета
- `V` — версия
- `D` — прямые зависимости через пробел

Программа ищет блок, где имя и версия совпали с параметрами,
и печатает зависимости по одной на строку. Если поля `D` нет,
печатает `зависимостей нет`.

Токен, который начинается с `!`, в Alpine означает конфликт
с другим пакетом. Это не зависимость, поэтому такая строка
не печатается.

Пример репозитория основной ветки Alpine 3.21:

```
https://dl-cdn.alpinelinux.org/alpine/v3.21/main/x86_64/
```

Команда `apk` при этом не запускается. Индекс читает сама
программа: стандартные `urllib` и `tarfile`.

С этапа 3 на экран выводится уже весь граф, а не только
прямые зависимости. Поле `D` по-прежнему читается из индекса.

## Этап 3. Граф

Граф строится обходом в ширину. Программа держит очередь
пакетов и список уже виденных. Рекурсии нет. Пакет, который
уже видели, в очередь второй раз не ставится, поэтому цикл
не крутит программу бесконечно. Ребро цикла на графе остается.

После обхода отдельно печатается строка `цикл: ...`, если
такие пакеты есть. Ромб, где две ветки сходятся в один пакет,
циклом не считается.

Имя с подстрокой из `--filter` в граф не входит.

В тестовом режиме `--repo` — это файл. Каждая строка начинается
с имени пакета, дальше через пробел его прямые зависимости.
Имена — большие латинские буквы:

```
A B C
B D
C D
D
```

Зависимость apk вида `so:...` или `/bin/sh` — это не имя пакета,
а то, что пакет предоставляет в поле `p`. Программа ищет пакет
с таким `provides`. Если их несколько, берет тот, у кого больше
число в поле `k`. Так `/bin/sh` в Alpine 3.21 ведет к
`busybox-binsh`, а не к `dash-binsh`.

Если у зависимости есть версия (`имя=1.2.3-r0`, `>=`, `~`),
версия сравнивается по правилам apk.

## Функции и настройки

`parse_args` разбирает аргументы и проверяет каждый параметр.
`format_config` собирает текст из пар ключ=значение.
`main` проверяет параметры, строит граф и печатает его.
Класс `Config` хранит уже проверенные значения.
`ConfigError` — ошибка в параметре.
`DataError` — ошибка сети, архива, файла или поиска пакета.
`load_index` скачивает `APKINDEX.tar.gz` и разбирает его.
`load_package` находит в индексе пакет нужной версии.
`direct_text` возвращает прямые зависимости так, как они
записаны в поле `D`.
`parse_index` разбирает текст индекса без сети.
`Index.resolve` превращает токен зависимости в имя пакета.
`Index.forward` строит таблицу прямых зависимостей репозитория.
`compare` и `version_matches` сравнивают версии Alpine.
`load_test_repo` читает тестовый файл графа.
`load_forward` выбирает тестовый файл или индекс Alpine.
`bfs_graph` обходит зависимости в ширину.
`format_graph` печатает ребра и строку про цикл.
`skipped` проверяет, попадает ли имя под фильтр.

## Сборка и тесты

Собирать проект не нужно: это скрипт на Python.

Тесты из корня репозитория:

```
python -m unittest discover -s tests -v
```

Запуск программы (Linux: `sh run.sh` с теми же аргументами):

```
run.bat --package zlib --version 1.3.2-r1 --repo https://dl-cdn.alpinelinux.org/alpine/v3.21/main/x86_64/
```

## Примеры

Цепочка из `tests/data/chain.txt`:

```
run.bat --package A --repo tests/data/chain.txt --test
```

```
A -> B
B -> C
```

Ветвление из `tests/data/branch.txt` печатает четыре ребра
и не пишет слово `цикл`. Цикл из `tests/data/cycle.txt`:

```
A -> B
B -> C
C -> A
цикл: A B C
```

Фильтр `D` на том же ветвлении убирает пакет `D`:

```
run.bat --package A --repo tests/data/branch.txt --test --filter D
```

```
A -> B
A -> C
```

Реальный пакет `alpine-baselayout` версии `3.6.8-r1`
из репозитория Alpine 3.21 main x86_64:

```
alpine-baselayout -> alpine-baselayout-data
alpine-baselayout -> busybox-binsh
busybox-binsh -> busybox
busybox -> musl
```

На этапе 2 прямая зависимость `zlib` выглядела так:

```
so:libc.musl-x86_64.so.1
```

У `musl` своих зависимостей нет: `зависимостей нет`.

На первом этапе те же параметры печатались парами:

```
package=musl
repo=https://example.com/alpine
test=false
version=1.2.5-r12
filter=
```

Ошибка, если забыть версию:

```
run.bat --package musl --repo https://example.com/alpine
```

Ответ: `ошибка: не задана версия пакета`

Ошибка, если имя пакета с большой буквы:

```
run.bat --package Musl --repo https://example.com/alpine --version 1.0
```

Ошибка, если фильтр состоит из пробелов:

```
run.bat --package musl --repo https://example.com/alpine --version 1.0 --filter "   "
```
